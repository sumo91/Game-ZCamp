## 0. 文档职责

本 UI Bible 负责把玩法状态转化为可实现、可验证的界面规范，统一：

- 主战场信息架构、尺寸、层级与安全区；
- HUD、城墙、5×3 建筑格、四卡手牌和商店的组件规则；
- 商店、倒计时、战斗、强化、暂停与结算的状态流转；
- 点击、选择、建造、升级、维修和错误反馈；
- 响应式、触控、文字、图标、动效、无障碍与验收标准；
- Phaser 表现层和 `src/core` 确定性状态之间的边界。

职责边界：

| 文档 | 负责 | 不负责 |
|---|---|---|
| 产品概述 | 规则、资源、波次、商店与胜负流程 | 像素尺寸和组件外观 |
| Art Bible | 气质、色彩、材质、造型、动画语言 | 每个界面的完整状态表 |
| UI Bible | 布局、组件、交互、状态、适配、验收 | 改写核心玩法数值 |
| 布局 SVG | 直观展示一个代表性画面 | 作为唯一规范来源 |

冲突优先级：玩法规则以产品概述和 `src/core` 的已批准设计为准；视觉气质以 Art Bible 为准；界面布局与交互以本 UI Bible 为准。

标记约定：

- **已定**：已获得方向确认，后续只做有证据的微调；
- **工作标准**：实现首版按此执行，真机验证后允许调整；
- **待定**：需要产品选择或可点击原型验证；
- **实现债务**：当前运行版本与目标规范不一致。

## 1. UI 北极星

### 1.1 一句话方向【已定】

> **绝大部分屏幕属于尸潮，玩家只守着底部一小块营地；信息像休闲手游一样直接，防线像微缩模型一样可信。**

### 1.2 五条设计原则【已定】

1. **先感到危险，再看到操作。** 敌军区是画面绝对主体，HUD 不得把战场切碎。
2. **城墙是失败目标，不是装饰分隔线。** 耐久与攻墙反馈必须贴着墙体出现。
3. **15 格始终可数、可点、可记忆。** 视觉可以融入场景，但不能让玩家误读格数。
4. **手牌负责建造，不负责开波。** 主战场没有“开始战斗”或“开始下一波”按钮。
5. **状态变化比装饰更快。** 选择、合法性、消费、受击和倒计时必须立即可读。

### 1.3 明确不做【已定】

- 不把营地扩大到与敌军区势均力敌；
- 不用顶部大横条永久占据战场高度；
- 不把 5×3 画成电子表格或开发调试面板；
- 不照搬《皇室战争》的循环牌序、下一张牌或圣水规则；
- 不在主战场放开波、重开、设置等低频大按钮；
- 不依赖悬停、右键、键盘或精确拖拽完成主要操作；
- 不用纯颜色作为可用、禁用、危险或选中的唯一提示。

## 2. 基准画布与安全区

### 2.1 逻辑画布【已定】

- 设计分辨率：720×1280；
- Phaser 缩放：`Phaser.Scale.FIT`；
- 对齐：水平、垂直居中；
- 关键内容安全边距：左右 24px，顶部 24px，底部 24px；
- 触控坐标、布局和动画均使用逻辑像素，不依赖设备物理像素；
- 游戏画布内不滚动，所有核心操作在单屏完成。

### 2.2 D3 空间骨架【已定】

| 区域 | 建议屏高 | 720×1280 起始坐标 | 目的 |
|---|---:|---:|---|
| 尸潮战区 | 约 56% | `y=0～724` | 数量、纵深、Boss、危险方向 |
| 城墙 | 约 4% | `y=708～772`，与上下区域局部叠压 | 最后防线、耐久、攻墙反馈 |
| 5×3 建筑区 | 约 25% | `y=772～1090` | 15 格与已建营地 |
| 资源 / 补给轨道 + 四卡手牌 | 约 15% | `y=1090～1280` | 双资源、补给进度、选择与成本 |

坐标允许局部重叠：城墙可压住战区与格区边缘，手牌可用阴影覆盖格区底边。语义顺序不得改变。

### 2.3 比例判断标准【已定】

- 第一眼必须感到“敌人多、阵地小”；
- 尸潮战区必须明显大于城墙、建筑区和手牌区中的任何一个区域；
- 城墙与玩家城市合计不得形成画面上半部的视觉重心；
- 增加可用高度时，优先延长敌人纵深，不放大玩家城市；
- 建筑区必须完整显示 5 列×3 行，不能通过滚动、分页或裁切补足。

### 2.4 《皇室战争》截图对比结论【工作标准】

本轮对比使用三类证据：用户提供的完整观战截图、Supercell / Apple 官方商店与产品素材、官方 CRL 真实赛事录像。观战画面会同时展示上下双方手牌，营销图会裁掉或重排 HUD，因此只从多类画面共同稳定的特征中提炼规则，不直接照抄单张截图比例。

《皇室战争》长期稳定的不是某套竞技场皮肤，而是以下空间纪律：

1. **竞技场是画面主体。** 中央战斗空间远大于顶部状态与底部手牌；UI 贴边，不把战场切成多个面板。
2. **玩法几何稳定。** 河流、桥、塔和部署区位置不随竞技场主题变化；主题只替换地表、边缘装饰、材质与气氛。
3. **固定空间锚点。** 王塔、公主塔、河流与桥让空场也能一眼看懂局势，高密度交火时仍可定位。
4. **战场中心安静、边缘丰富。** 大块低对比地表留给单位和 VFX，装饰密度集中在外围。
5. **单位比地表更鲜艳。** 地面承担空间，角色、法术、血条和资源承担高饱和色。
6. **手牌是独立稳定的操作层。** 战斗再激烈，四牌的位置、成本和资源都不被 VFX 推挤或覆盖。
7. **信息贴着对象。** 塔生命、等级和单位状态靠近对应对象，不集中挤进顶部 HUD。

对 ZCamp 的转换关系：

| 《皇室战争》 | ZCamp 对应物 | 转换规则 |
|---|---|---|
| 竞技场主体 | 尸潮区 + 城墙 + 营地 | 世界画面全屏连续，不套大面板 |
| 河流 / 双桥 | 横向城墙 | 作为唯一强水平分界和失败锚点 |
| 三座塔 | 5×3 营地建筑 | 提供稳定空间记忆，但不做上下镜像 |
| 四张手牌 | 四张建筑卡 | 借位置、体量和状态，不借循环牌序 |
| 圣水 | 木材 / 建造资源 | 借“资源靠近手牌”，不照搬有上限的圣水条 |
| 红蓝阵营 | 冷尸潮 / 暖营地 | 用冷暖和轮廓区分，不复制 PvP 阵营色 |

### 2.5 关键战场构图【已定】

- 画面使用“一条竖向压力轴 + 一条横向防线”：尸潮自上向下，城墙横切画面；
- 敌军入口、Boss、主攻墙点与营地核心尽量落在中轴附近，形成清楚的纵向叙事；
- 城墙是全屏最强的水平线，但厚度必须克制，不能像大型城堡平台；
- 5×3 网格是紧凑的后方阵地，不与尸潮区竞争面积；
- 手牌贴底且始终稳定，和世界画面通过阴影、台阶或材质边界分开；
- 主要交火点位于城墙上方，和底部手指操作区保持明显距离；
- 左右边缘允许树木、废车、围栏、岩石和雾形成框景，中心通道保持低噪声。

### 2.6 空场也必须成立【已定】

《皇室战争》没有单位时，塔、河流、桥和地表已经构成完整竞技场。ZCamp 同样不能依赖尸潮与 VFX 掩盖空洞底图。

空场必须具备：

- 从暗处通向城墙的连续推进通道；
- 至少三个纵深层次：远雾、主战地面、城墙前缓冲区；
- 城墙、门和两侧灯火形成明确终点；
- 地面用车辙、裂纹、脚印或碎石暗示推进方向，但不画显眼箭头；
- 画面边缘的叙事装饰比中心密集；
- 中央地面的明度比最暗边缘高约 8%～12%，自然聚焦单位；
- 即使隐藏所有 UI，也能看出“敌人从上方来，下面这条墙必须守住”。

### 2.7 战斗单位与场景尺度【工作标准】

以 720px 画布宽为基准：

| 对象 | 建议可见宽度 | 视觉职责 |
|---|---:|---|
| 普通僵尸 | 30～44px | 形成群体数量，不抢单体焦点 |
| 快速敌人 | 26～38px | 更瘦、更前倾，靠步频识别 |
| 重装 / 精英 | 52～72px | 打破尸群节奏，成为次级焦点 |
| Boss | 88～124px | 战场一级焦点，但不宽到堵死通道 |
| 建筑主体 | 64～92px | 可越出地基，但不得覆盖相邻核心热区 |
| 城墙门 / 核心锚点 | 120～180px | 建立最后防线和主攻点 |

单位使用稳定接地阴影。普通敌人不常驻大地环；精英、Boss 和技能预警才使用明显地面形状。

### 2.8 视觉层级【已定】

静态与动态元素按以下顺序争夺注意力：

1. 城墙濒破、Boss 技能和直接失败风险；
2. 当前主要交火、爆炸、冲锋和控制；
3. Boss / 精英轮廓及其生命状态；
4. 当前选中卡、合法建造格和资源可支付性；
5. 城墙耐久、波次与剩余敌人；
6. 四张手牌与普通建筑状态；
7. 普通僵尸、环境动画与装饰。

任何新元素必须声明自己属于哪一层。低层元素不能通过更大面积、更高饱和或持续闪烁压过高层元素。

### 2.9 色彩与材质转换【已定】

- 《皇室战争》的竞技场主题可以大幅换色，但功能 UI 保持稳定；ZCamp 同样保持 HUD、卡壳、成本和危险语义稳定；
- 大面积地表使用中等明度、低到中饱和的蓝绿色；最深色集中在边缘、UI 阴影和少量纵深处，不能让可玩地面大面积接近黑色；
- 僵尸灰绿、枪火、冰、电和危险红承担局部高饱和，不给每块格子或每张卡持续彩色描边；
- 四张卡默认共用同一套深色金属 / 木质卡壳。塔种功能色集中在插画、角标和选中内辉；
- 方案 H 当前四张卡的全彩外描边视为线框稿占位，正式稿改为统一中性卡壳；
- 场景、单位、建筑和 UI 共享同一受光方向；卡牌可以更亮，但不能像来自另一款游戏；
- 文字和数值使用浅色内容 + 深色描边 / 底板，避免依赖纯白发光解决复杂背景可读性。
- 视觉压力来自敌人数量、推进距离和城墙风险，不通过写实材质、压黑曝光或恐怖光照制造；
- 场景使用大色块、柔和阴影和低频纹理；僵尸采用大头、短肢和夸张表情，保持休闲玩具感。

### 2.10 高密度战斗纪律【已定】

- VFX 可以穿过世界层，不能进入 HUD 与手牌层；
- 普通敌人满血时可隐藏血条，受伤后短暂显示；
- 同屏生命条优先 Boss、精英、正在攻墙者和当前目标；
- 同类普通伤害数字合并或抽样，避免形成数字墙；
- 地面范围提示在单位下方，弹道在单位上方；
- 尸群通过前后遮挡、体型、步频和轻微明度变化形成纵深，不给每只敌人加彩色描边；
- 爆炸、冰冻和电弧的最亮区域短暂出现，结束后迅速回到低噪声地表；
- 城墙耐久、倒计时、选中卡和成本徽记不受屏幕震动影响。

## 3. 主战场层级

从后到前的推荐显示层级：

1. 战场底图、边缘森林、雾；
2. 尸潮通道与地面范围提示；
3. 敌人、Boss、敌人血条；
4. 弹道、受击和掉落；
5. 城墙、城墙耐久、攻墙反馈；
6. 5×3 地基、建筑和建造预览；
7. 顶部 HUD、底部手牌与消息提示；
8. 商店、强化选择、暂停和结算遮罩；
9. 系统级确认与错误。

高层弹窗出现时，低层战斗仍可作为背景，但不得继续响应被遮挡区域的输入。

## 4. 顶部 HUD

### 4.1 信息分组【工作标准】

顶部 HUD 叠加在尸潮区，不单独占一条实体导航栏。

| 位置 | 内容 | 常态 |
|---|---|---|
| 左上 | 金币或非建造资源 | 图标 + 短数字 |
| 上中 | 当前波次 / 总波次 | `第 8 / 20 波` |
| 上中第二行 | 剩余敌人、精英/Boss 提示 | 情境显示 |
| 右上 | 暂停 | 图标按钮 |
| 城墙中部 | 城墙耐久 | 嵌入墙体显示，不重复放在顶部 |
| 格区与手牌之间 | 资源 / 补给 | 木材与金币当前值 + 下一张牌横向进度 |

### 4.2 HUD 规则【已定】

- 不显示游戏标题、引擎版本、调试标记或说明句；
- 数字使用固定宽度容器或等宽数字特性，资源变化不推挤其他组件；
- 普通战斗不显示秒级波次剩余时间，除非玩法规则需要；
- `剩余 46` 比百分比进度更容易理解，优先显示剩余敌人数量；
- Boss 出现时，上中组可临时切换为 Boss 名称与长血条；
- 暂停热区至少 56×56，图标视觉尺寸可以更小；
- 顶部 HUD 不承载建造、维修、重开和商店入口。

## 5. 城墙组件

### 5.1 结构【已定】

- 城墙横跨可见画面，是尸潮区和营地区的硬分界；
- 耐久条嵌在墙体中部或中央门体，不能漂到顶部 HUD，也不能靠近单座炮塔而被误认为建筑血条；
- 条内或条侧显示当前百分比；详细数值仅在选中或商店维修界面显示；
- 墙体破损覆盖层与耐久档位保持一致，详见 Art Bible；
- 僵尸接触墙体后必须表现明确的停步、攻击和受力点。
- 城墙本体不承载固定炮塔；所有机枪、火炮、冰冻和电磁塔只能位于 5×3 格内；
- 5×3 前排紧贴城墙后方，只保留一道很窄的结构接缝，不设置炮台走廊或额外平台。

### 5.2 耐久状态【工作标准】

| 状态 | 耐久 | UI 表现 |
|---|---:|---|
| 健康 | 76%～100% | 低权重耐久条，稳定暖光 |
| 受损 | 51%～75% | 条轻微变暖，墙体裂纹出现 |
| 危险 | 26%～50% | 危险色、短促受击脉冲、维修提示可出现 |
| 濒破 | 1%～25% | 高对比危险色、低频警示，不持续闪屏 |
| 失守 | 0% | 耐久归零、墙体破口、输入转入失败流程 |

维修入口是情境操作：点击墙体或商店内维修项进入，不做常驻大按钮。

## 6. 5×3 建筑区

### 6.1 网格【已定】

- 固定 5 列×3 行，共 15 格；
- 格子编号稳定，建议数据标识采用 `slot-r{row}-c{column}` 或等价结构；
- 战斗、商店和倒计时之间不移动网格、不交换编号；
- 15 个视觉地基必须由同一个母版格复制：同行同宽、同列同高、圆角与边框一致，四条纵分隔线和两条横分隔线连续对齐；
- 可以对整块棋盘统一施加轻度 3/4 透视，但不能逐格独立变形，不能出现错列、扩格、缩格、高矮不一或宽窄不一；
- 单格触控热区至少 56×56，格间至少保留 8px 可辨间隔；触控热区不得随视觉透视缩小；
- 建筑锚点和底座中心必须与格子中心重合；底座与接触阴影完整位于单格内，不压线、不跨格、不悬空；
- 建筑上部轮廓可以为了体积感越出视觉地基，但不能侵入相邻格的核心点击区域、状态边缘或遮挡相邻建筑底座。

### 6.2 位置语义【工作标准】

| 排 | 位置意义 | 优先建筑 |
|---|---|---|
| 前排 | 贴近城墙，火力和维修覆盖最好 | 防御塔、修理所 |
| 中排 | 防御与运营折中 | 防御塔、主城、功能建筑 |
| 后排 | 营地内部，强化经营感 | 伐木场、主城、运营建筑 |

### 6.3 格子状态【已定】

| 状态 | 视觉 | 输入 |
|---|---|---|
| 常态空格 | 低对比地基、铆钉或木框 | 点击不动作，除非已有选中卡 |
| 合法 | 暖白边缘或选中卡功能色，轻呼吸一次 | 点击建造 |
| 非法 | 降亮、禁用形状标记 | 点击给出原因，不消费资源 |
| 已占用 | 建筑 + 等级信息 | 点击打开建筑详情/升级 |
| 当前目标 | 高对比边缘 + 半透明建筑预览 | 再次确认或松手落位 |
| 危险影响 | 地面警示置于建筑下方 | 不阻断选择，除非玩法规定 |

合法格只在选中建筑卡后统一显现；常态下不让 15 个格框持续高亮。

## 7. 底部四卡手牌

### 7.1 结构【已定】

参考《皇室战争》的手牌布局语言，不复制其卡组规则：

- 四张竖卡横向排列；
- 成本徽记固定在左上；
- 建筑图标是卡面最大信息；
- 名称位于卡片底部；
- 四张卡默认使用统一中性卡壳，功能色只进入图标、角标和局部内辉；
- 当前选择上抬 6～10px，并使用暖白外轮廓 + 对应功能色内辉；
- 横向资源 / 补给轨道固定在格区与卡牌之间，左端并列显示真实木材、木材产速和金币；
- 横向进度条只表示“下一张牌”的 18 秒补给进度，不再表示木材库存或“距离下一张可建”；
- 每张卡的成本徽记包含对应资源图标和当前真实费用，不能只显示无语义数字；
- 每张卡以自下而上的卡面背景填充表示当前资源相对该牌费用的支付进度；
- 卡牌顺序固定，不因选择、消费或波次发生换位。

成本徽记的借鉴点是“固定压在卡片角部、与卡面组成一个整体”，不是照抄《皇室战争》某一时期的具体角位。ZCamp 首版采用左上，是为了给底部中文名称留出稳定空间；若真机拇指遮挡测试显示右上更清楚，可以整套统一迁移，但四张卡不得混用不同角位。

横向资源 / 补给轨道继续承担 5×3 世界区与四卡 UI 区之间的视觉分界，但不再显示木材百分比。木材没有容量上限，用全局横条表达 `当前木材 / 某张牌费用` 会产生目标不明、目标随手牌变化和重复文案等问题。轨道左侧只显示真实库存与产速；轨道中央使用确定的 `补给进度 / 18 秒周期`，并同时显示下一张牌名称和剩余时间。手牌已满且已有完成等待的补给牌时，进度保持满格，文案改为“待入手：牌名 · 腾出手牌”；开局倒计时和战术暂停期间进度冻结。禁止同时保留“距可建还差 N”的全局木材进度。

720×1280 工作尺寸：

| 属性 | 建议值 |
|---|---:|
| 单卡宽 | 126～136px |
| 单卡高 | 150～170px |
| 卡间距 | 8～12px |
| 圆角 | 16～18px |
| 成本徽记 | 38～42px |
| 资源 / 补给轨道 | 高 24～32px；横跨四卡组宽度 |
| 上抬距离 | 6～10px |
| 手牌左右安全边距 | 至少 24px |

### 7.2 卡牌内容来源【已定】

- 四格显示当前动态手牌，可包含基地、永久和战术三类牌；
- 卡牌内容必须来自类型化内容定义，不在场景中散写名称、成本和颜色；
- 牌序、四格上限、18 秒补给、满手等待与下一张牌预览遵循阶段版本设计；
- 经济建筑、工程 / 修理、永久发展与战术牌使用同一套手牌组件和支付状态语言。

### 7.3 卡牌状态【已定】

| 状态 | 视觉 | 行为 |
|---|---|---|
| 支付进度 | 对应资源色从卡底向上填充；液面线横贯卡面 | 只表达当前资源 / 当前费用，不代表硬条件 |
| 可用 | 填充达到 100%，完整亮度、亮边或“可用”短标记 | 可选择 |
| 选中 | 上抬、暖白外轮廓、功能色内辉、合法格显现 | 再点取消，点格建造 |
| 资源不足 | 填充未满，未填充区保持中性深色；卡面只常驻资源图标与费用 | 点击显示“还差 N 木材 / 金币”，不进入选中态 |
| 暂不可建 | 锁形遮罩 + “已达上限 / 无合法目标”等短原因；不显示伪支付进度 | 不进入选中态，可通过弃牌模式处理 |
| 按下 | 70～100ms 压缩至约 0.96 | 立即反馈，不等待命令结果 |
| 建造成功 | 资源数值扣减、建筑落地、卡恢复常态 | 同一指令只消费一次 |

#### 7.3.1 卡面纵向支付进度【已定】

每张非硬锁定卡的填充高度为：

`clamp(当前对应资源 / 当前显示费用, 0, 1)`

- 基地牌使用木材；永久牌和战术牌使用金币；
- 基地牌的“当前显示费用”必须是此刻所有合法动作中的最低真实费用：空格建造为基础费，只剩同类升级目标时使用最低真实升级费，工程 / 修理牌包含城墙动作；
- 永久和战术牌使用内容定义中的金币费用；
- 若不存在合法动作，或永久牌已达应用上限，进入硬锁定状态，不用 0% 填充冒充资源不足；
- 填充从卡底向上裁切在卡壳内部，木材使用暖木色 / 琥珀色，金币使用亮金色；未填充区保持统一中性深色；
- 使用 1～2px 清晰液面线帮助四张牌横向比较；文字、图标和费用始终位于填充层之上并保持可读；
- 资源增长、击杀得金和支付会让所有共用该资源的卡同步变化。表现层可在 120～220ms 内平滑追随真实值，但不得延迟命令结果；
- 跨过 100% 时允许一次 180～260ms 的边框亮起，不持续闪烁；支付后液面同步下降；
- 战术暂停期间不会自动产出木材、获得战斗金币或推进补给，因此无玩家操作时液面冻结；暂停中主动支付仍应立即更新；
- 费用数字与填充分母必须来自同一派生结果，禁止卡面写 60、实际却按 90 填充。

#### 7.3.2 信息减法【已定】

- 删除全局“距可建还差 N”；
- 删除卡面常驻“费用 · 木材 / 金币”和“还差 N”长句，改为资源图标 + 数字成本；
- 资源不足的精确差额只在点击该牌后的局部 Tip 中出现；
- 可用状态采用满液面 + 亮边 / 短标记，不靠颜色单独表达；
- “拆除”只在选中可拆建筑时占用右侧情境按钮；默认入口为“弃牌”，弃牌模式中变为“取消”。

### 7.4 MVP 输入模型【工作标准】

首版主要操作使用“点击卡牌 → 点击格子”：

1. 点击卡牌进入选中；
2. 15 格统一显示合法性；
3. 点击合法空格发送建造命令；
4. 命令接受后扣除资源并播放落地反馈；
5. 命令拒绝时保持状态一致，并显示明确原因。

拖动卡牌到格子可以作为增强输入，但不得成为唯一操作方式。点击与拖动最终必须发送同一种核心命令，不能产生两套规则。

## 8. 波间商店

### 8.1 进入与退出【已定】

- 每波敌人清空后自动进入商店；
- 第 1 波前先进入初始商店；
- 商店没有强制停留时限；
- 玩家关闭商店即表示整备完成；
- 商店关闭后不能出现第二个“开始波次”确认；
- 商店关闭后立即进入 3 秒倒计时。

### 8.2 布局【工作标准】

- 商店优先占用上方尸潮战区，保留城墙、5×3 网格和四卡手牌的空间记忆；
- 背景战场降亮、降对比，不能让敌人残影与商品卡竞争；
- 商店标题和关闭操作位于商店面板顶部；
- 商品/强化内容使用单层卡片，不在卡片内继续嵌套卡片；
- 关闭操作可以写“完成整备”或使用明确关闭图标，但它属于商店界面，不属于主战场；
- 商店关闭前允许建造、升级、维修、强化和挑战选择，具体可用项由玩法状态决定。

### 8.3 商店状态【工作标准】

| 状态 | 界面反馈 |
|---|---|
| 刚进入 | 面板从上方战区淡入/下落，战场降亮 |
| 可购买 | 商品显示成本、效果和当前资源 |
| 资源不足 | 商品降亮，成本差额明确 |
| 已购买 | 立即更新资源与相关建筑/属性，不保留假按钮 |
| 准备关闭 | 关闭操作反馈立即开始 |
| 已关闭 | 面板退出，转入不可交互的 3 秒倒计时 |

## 9. 自动开波倒计时

### 9.1 规则【已定】

- 固定 3 秒；
- 显示 `3`、`2`、`1`，不显示可点击按钮；
- 倒计时位于尸潮战区视觉中心或入口附近，不遮挡城墙耐久和手牌；
- 倒计时期间不重新打开商店；
- 是否允许继续建造由产品规则决定；首版建议保留手牌可见但暂时不接收新的建造指令，减少状态竞争；
- `1` 结束后，入口脉冲、波次 HUD 更新、敌人开始生成。

### 9.2 技术边界【已定】

倒计时是玩法状态，不是 Phaser 装饰计时器：

- 倒计时剩余时间保存在 `src/core` 的游戏状态；
- 使用固定步长时钟推进；
- 暂停、后台恢复和重开必须得到确定结果；
- Phaser 只读取状态并播放数字切换、入口脉冲和声音；
- 禁止只在 `GameScene` 中使用 `setTimeout`、Tween 完成回调或墙钟时间直接开波；
- UI 不再直接暴露玩家可调用的 `start_wave` 按钮命令。

## 10. UI 状态流

### 10.1 主循环【已定】

```text
初始商店
  → 关闭商店
  → 3 秒倒计时
  → 战斗
  → 敌人清空
  → 波间商店
  → ……
  → 第 20 波胜利 / 城墙归零失败
```

### 10.2 表现状态与核心状态映射【工作标准】

| UI 表现状态 | 目标核心状态 | 主要可见层 | 主要输入 |
|---|---|---|---|
| 初始商店 | `SHOP` | 商店、营地、手牌 | 购买、建造、关闭 |
| 波间商店 | `SHOP` | 商店、营地、手牌 | 购买、升级、维修、关闭 |
| 自动倒计时 | `COUNTDOWN` | 战场、营地、手牌、数字 | 暂停；其他输入按规则限制 |
| 战斗 | `COMBAT` | 完整主战场 | 建造、升级、维修、暂停 |
| 强化选择 | `UPGRADE` 或商店子状态 | 三选一弹层 | 选择一项 |
| 暂停 | `PAUSED` | 暂停面板 | 恢复、设置、退出确认 |
| 胜利 | `VICTORY` | 结算 + 暖光战场 | 继续、重开 |
| 失败 | `DEFEAT` | 结算 + 破墙战场 | 重开、退出 |

`SHOP` 与 `COUNTDOWN` 是目标状态名称，最终命名可调整，但状态语义必须存在于核心层。

### 10.3 输入阻断【已定】

- 商店遮住的战场区域不接收战场点击；
- 强化三选一出现时，背景建造和暂停以外的输入冻结；
- 暂停后核心时钟停止，所有战斗与倒计时动画进入暂停或安全静止；
- 胜负结算后不再接受建造、升级和维修命令；
- 同一指针事件不能同时触发卡牌选择和格子建造。

## 11. 强化、暂停与结算

### 11.1 强化三选一【工作标准】

- 战场保留可见但降亮；
- 三张选择纵向堆叠或在足够宽度时横排，720×1280 首选纵向；
- 每张至少包含名称、效果、受益对象图标；
- 只允许选择一项，点击后立即锁定其他项；
- 生效反馈从卡片流向对应塔、城墙或资源区；
- 长说明允许换行，但不能通过极小字体塞入卡片。

### 11.2 暂停【工作标准】

- 暂停按钮位于右上；
- 面板包含继续、设置、重新开始、退出；
- 重新开始和退出必须二次确认；
- 不把“暂停 / 恢复”做成战场中部常驻文字按钮；
- 后台隐藏自动进入暂停，恢复后不跳过倒计时。

### 11.3 结算【工作标准】

- 胜利保留营地暖光和战场结果；
- 失败保留墙体破口和敌人越线；
- 优先展示波次、存活/失守、关键构筑和奖励；
- 重开只在结算或暂停确认中出现；
- 不在结算前短暂闪回可操作主战场。

## 12. 消息与错误反馈

### 12.1 反馈优先级【已定】

1. 城墙濒破、Boss 技能、失败风险；
2. 商店关闭与 3 秒倒计时；
3. 当前选择、合法格和资源不足；
4. 建造、升级、维修成功；
5. 普通资源获得和说明性消息。

### 12.2 消息规则【工作标准】

- 常规提示显示 1.2～1.8 秒；
- 相同资源不足消息在短时间内合并，不堆叠；
- 错误写明原因，例如“还差 15 木材”，不只写“无法建造”；
- 消息避开波次 HUD、城墙耐久和四卡成本徽记；
- 成功动作优先通过对象本身反馈，减少顶部 Toast；
- 禁止把长期操作说明常驻在战场中。

### 13.2 图标【已定】

- 不使用写实照片、细线军事图标或风格不统一的 Emoji；

### 13.3 UI 语义色【已定】

具体色值由 Art Bible 统一维护，本表只定义用途：

| 语义 | 用途 |

## 14. 动效与声音接口

### 14.1 UI 动效【工作标准】

| 事件 | 时长 | 表现 |
|---|---:|---|
| 卡片按下 | 70～100ms | 压缩至约 0.96 |
| 卡片选中 | 120～180ms | 上抬、描边切换 |
| 合法格显现 | 120～180ms | 一次淡入，不持续剧烈呼吸 |
| 建筑落地 | 240～320ms | 下落、轻弹、尘圈 |
| 商店进入/退出 | 200～300ms | 面板移动 + 背景明暗变化 |
| 倒计时数字 | 每秒一次 | 数字缩放落定，禁止循环抖动 |
| 资源扣除 | 180～260ms | 数字变化；如未来存在容量条，再同步回退 |
| 错误反馈 | 100～160ms | 小幅横向拒绝，不震全屏 |

### 14.2 声音与触觉接口【待定】

- 卡牌选中：轻点击；
- 建造成功：落地 + 资源消费；
- 资源不足：短促低音；
- 倒计时：三个同节奏提示音，最后开波音更强；
- 城墙濒破：低频警报，避免持续刺耳；
- 触觉反馈在 Web / 小程序能力允许时启用，并提供关闭选项。

---

## 15. 响应式与设备适配

### 15.1 适配原则【已定】

- 以 720×1280 设计，使用 FIT 等比缩放；
- 更长屏幕优先增加尸潮区纵深和顶部安全区；
- 更矮屏幕优先压缩环境留白、卡片上下内边距和格区间距；
- 不通过隐藏一排格子、减少卡牌或裁切城墙解决适配；
- 重要文本与交互远离系统手势区域；
- 横屏不是 MVP 主布局，横屏进入时可提示旋转设备。

### 15.2 最低可读与触控标准【工作标准】

- 主交互热区至少 56×56 逻辑像素；
- 相邻高风险操作之间至少 8px 间隔；
- 360px 宽截图下仍能认出四张卡、15 格、城墙和 Boss；
- 卡片名称过长时优先使用短名称，不把字号降至不可读；
- 设备安全区变化不能覆盖暂停、成本徽记或最底部手牌。

---

## 16. 无障碍与舒适度

- 所有状态至少用“颜色 + 形状/文字/动作”双重编码；
- 危险与可用不能只依赖红绿差异；
- 提供降低震动、降低闪烁和关闭触觉的设置入口；
- 高频闪烁避免超过每秒 3 次；
- 倒计时同时使用数字、声音和入口节奏，不只依赖颜色；
- 暂停与后台恢复不得让玩家丢失商店选择或跳过倒计时；
- 关键操作不依赖拖动，保证行动不便或单手操作玩家可以点击完成。

## 17. Phaser 实现边界

### 17.1 核心层职责【已定】

以下状态和规则属于 `src/core`：

- 15 个固定格及稳定标识；
- 商店、倒计时、战斗、强化、暂停、胜负状态；
- 3 秒倒计时推进与自动开波；
- 卡牌/建筑定义、成本、可用性与建造结果；
- 资源扣除、建筑升级、维修和拒绝原因；
- 暂停、后台恢复和重开的确定性结果。

核心层不得依赖 Phaser、DOM、Tween、系统墙钟或美术资源是否加载成功。

### 17.2 Phaser 层职责【已定】

`src/phaser` 负责：

- 根据核心状态摆放 HUD、格子、手牌和弹层；
- 将点击/拖动翻译为类型化游戏命令；
- 播放视觉、声音和触觉反馈；
- 维护显示对象池和输入热区；
- 响应画布缩放与设备安全区；
- 不自行决定资源、合法格、倒计时结束或下一波生成。

### 17.3 内容数据【已定】

- 卡名、成本、图标键、功能色键、描述和解锁条件来自类型化内容定义；
- UI 不根据显示名称推断塔种；
- 新增建筑或塔时，通过内容校验进入 UI，不在 `GameScene` 中追加散落分支；
- 拒绝原因应使用稳定原因码，在 UI 层映射为玩家可读文字。

## 18. 当前实现债务

当前运行版本是功能原型，不代表目标 UI。已知差异：

| 当前实现 | 目标规范 | 影响 |
|---|---|---|
| `GameScene` 使用 5×2，共 10 格 | 5×3，共 15 格 | 与产品空间规则不一致 |
| 主战场有“开始第 X 波”按钮 | 关商店后 3 秒自动开波 | 流程和信息层级不一致 |
| 核心只有 `PREPARE`，无 `SHOP` / `COUNTDOWN` | 商店与倒计时为核心状态 | 暂停、恢复和确定性风险 |
| 四塔是 142×42 矩形按钮 | 四张竖向手牌 | 识别、触控与商品感不足 |
| 建筑区位于画面底部并只有两排 | 城墙下方三排，手牌另占底部 | 方案 H 尚未落地 |
| HUD 为多行开发文本 | 紧凑信息胶囊 + 贴墙耐久 | 战场被信息切碎 |
| `SETUP READY` 与 Phaser 版本可见 | 玩家画面禁止开发标记 | 商品化截图不合格 |
| 重开、维修、暂停为战场大按钮 | 暂停图标、情境维修、结算重开 | 低频操作抢占战场 |

这些差异应在进入正式美术资产制作前按任务拆分，不应通过修改 Art Bible 来迁就当前原型。

## 19. 验收与视觉证据

### 19.1 五秒识别测试

未参与开发的人看战斗截图五秒，应能回答：

- 敌人从哪里来；
- 哪条墙不能被攻破；
- 玩家拥有多少建筑格；
- 底部四张卡用于什么；
- 当前最紧急的威胁是什么。

### 19.2 布局验收

- 敌军区占画面绝对主体；
- 5×3 共 15 格全部可见且可数；
- 15 格使用同一模板，行列分隔线连续对齐，不出现大小、高矮、宽窄或透视不一致；
- 每座建筑的锚点、底座和接触阴影均落在所属单格内，不跨格或偏离格心；
- 城墙、格区和手牌没有相互遮挡核心信息；
- 主战场不存在开波按钮；
- 木材、木材产速和金币紧邻卡牌，当前值与成本可以直接比较；
- 横向进度条只表达下一张牌的补给进度；满手等待、暂停和开局倒计时状态与核心规则一致；
- 四张卡分别以自下而上的真实支付进度表达 `当前资源 / 当前费用`，同资源卡可以直接横向比较；
- 每张卡的成本徽记均含对应资源图标；硬锁定、资源不足、可用和选中状态不只靠颜色区分；
- 城墙本体没有炮塔，耐久条嵌在墙体中部，5×3 前排紧贴墙后；
- 360px 宽截图仍保留四卡、15 格、城墙与敌人识别；
- 所有主要热区至少 56×56。

### 19.3 状态流程验收

- 波次清空后自动进入商店；
- 商店关闭后只出现 3 秒倒计时，不出现第二次确认；
- 倒计时结束自动生成下一波；
- 倒计时暂停、后台恢复与重开结果可复现；
- 资源不足、格子占用和非法建造都有明确拒绝反馈；
- 弹层出现时不会误触背景。

### 19.4 工程验证

- `npm run check` 通过；
- `npm run build` 通过；
- 核心状态流有自动化测试；
- 720×1280 和 360px 宽视觉截图通过人工检查；
- 浏览器控制台无新增错误；
- 玩家可见布局改动附带可复现截图或录屏。

## 20. 开放问题

1. 四卡手牌是否永久固定为四种防御塔，还是会包含伐木场、修理所等建筑；
2. 商店是仅占用上方尸潮区，还是在强化选择时允许全屏模态；
3. 3 秒倒计时期间是否允许继续建造；
4. 点击已占用建筑格后，是直接升级还是打开详情面板；
5. 战斗中是否允许拆除与换位，以及误触防护方式；
6. 金币、经验和挑战入口最终位于顶部 HUD 还是商店；
7. 中文正式字体、数字字体与小程序首包成本；
8. 刘海、安全区和超长屏的首批真机名单；
9. 是否加入卡牌拖放作为增强输入；
10. 商店关闭操作的最终文案是“完成整备”还是纯关闭图标。
11. 卡面支付液面在最终美术资产中的材质、边缘扰动与高亮强度；不得改变本版已经确定的进度语义。
