## 0. 当前事实源与边界

本文件描述阶段 D 候选运行版的玩家可见界面。当前运行版只使用新版 `buildingGrowth` 内容与成长建筑命令：箭塔、四种特殊塔、木材厂、波次、城墙、暂停、词条选择、改造和终局。

- 建造与升级支付木材；改造支付金币；数值与核心命令不在本文件中重写。
- 所有名称、角色、资源归属、费用、等级上限和词条说明来自 typed content 与纯 view model。
- Phaser 只读取核心状态、派生显示和输入优先级；`src/core` 不依赖 Phaser、DOM、Tween 或墙钟。
- 旧版动态手牌、补给、弃置、永久发展和战术动作不是当前候选版界面或运行时入口。
- 本文件中的“历史”只指旧版本记录，不构成当前实现要求。

冲突优先级：核心已批准规则 > Art Bible 视觉气质 > 本 UI Bible 的布局/交互 > 历史截图和旧版本记录。

## 1. 视觉北极星

绝大部分画面属于尸潮；玩家只在底部一小块营地上完成快速、直接的成长决策。中心战场保持低噪声，敌人、城墙和建筑承担主要视觉信息。

必须同时满足：

- 敌人从上方进入，城墙是唯一强水平失败锚点；
- 5×3 共 15 个格位始终完整、可数、可点；
- 建筑、词条、改造和终局信息靠近对象或位于清晰模态中；
- 关键状态使用颜色加文字/形状/动作的双重编码，不依赖颜色单独表达；
- 不出现玩家可见的开发标记、调试文本或开波按钮。

## 2. 逻辑画布与空间骨架

设计分辨率为 720×1280，Phaser 使用 FIT 等比缩放，左右安全边距 24px，底部安全边距 24px，画布不滚动。

| 区域 | 坐标 | 语义 |
|---|---|---|
| 尸潮区 | `x=24,y=0,w=672,h=724` | 纵深、群体、Boss、攻击反馈 |
| 城墙 | `x=24,y=708,w=672,h=64` | 耐久、护线、失败反馈 |
| 建筑格 | `x=24,y=772,w=672,h=318` | 5×3 成长建筑 |
| 资源轨道 | `x=24,y=1090,w=672,h=48` | 木材、木材产速、金币 |
| 情境操作区 | `x=24,y=1138,w=672,h=142` | 空格建造、建筑详情、拆除 |

格位使用稳定 `slot-r{row}-c{column}` 标识。每格约 128×94px，行距与列距保持一致；建筑锚点、底座和阴影不得跨格。

360px 宽通过 FIT 缩放完整显示上述逻辑画布，不隐藏格位，不减少动作。主要热区实际高度至少 56px，相邻高风险动作至少间隔 8px。

## 3. 顶部 HUD、城墙与资源

顶部只显示阶段、波次、下一波时间/首波准备、威胁数量和暂停入口。资源不在顶部重复显示。

城墙显示真实 `wallHp / wallMaxHp`，低于 35% 使用危险色并增加裂纹/受击反馈。城墙不放置炮塔，不把修理入口做成常驻大按钮。

资源轨道左侧就近显示：

- 自绘木材图形、真实木材值、真实木材产速；
- 自绘金币图形、真实金币值；
- 不伪造木材容量上限，不显示“距可建”或木材百分比。

资源产速来自 core 的共享 selector，与波次结算使用同一来源。暂停、词条选择、系统暂停和终局时不自动推进资源或战斗。

## 4. 情境操作与详情

空格被选中时显示两个动作：箭塔、木材厂。每个动作在点击前同时显示名称、职责/产出定位、木材图形和费用。

建筑被选中时显示：

- 名称、职责、等级与 typed content 派生的等级上限；
- 木材升级费用和升级状态；
- 箭塔的“改造”详情入口始终可打开，只要该建筑仍是箭塔且没有更高优先级模态；
- 可拆建筑的拆除入口；拆除零返还。

详情缺少 typed definition 时明确不显示未知费用/等级，不使用默认值猜测。

建造、升级、改造三类资源不足均使用降亮/禁用外观加短状态文字；点击后才显示准确差额，不扣资源、不改变选择。核心命令仍是最后权威。

## 5. 改造弹层

箭塔详情的改造入口不因金币不足而禁用。弹层展示机枪、火炮、冰冻、电磁四种职责与费用；只有具体选项依据金币状态禁用。

- 改造弹层打开时，背景格位、详情动作和暂停以外的下层热区全部阻断；
- 四个选项和返回按钮使用共享 bounds，同时服务绘制和纯命中判定；
- 点击合法选项后立即扣除金币，保留建筑等级和已有词条，核心重新计算对应战斗 profile；
- 返回不会穿透到格位或下层动作；改造后可继续升级并进入词条三选一。

## 6. 词条选择

升级成功后进入 `TRAIT_DRAFT`。战场保持可见但降亮，三选一纵向排列，每项至少显示：名称、职责分类、当前层数、选择后层数、最终累计效果。

累计文案由 typed effect 与 `nextStacks` 统一派生：百分比、固定产量、折扣封顶、波次储备和机制型词条不得在 GameScene 中散写分支。机制型效果至少写出“第 N 层”并保持数值与 content 一致。

词条模态打开时：

- 只有三个合法选项可点击；
- 格位、建筑动作、暂停下层热区全部 blocked；
- 选择一次后锁定，核心命令完成后返回升级前的可操作阶段；
- 在 TRAIT_DRAFT、系统暂停和终局中，核心时间、木材、敌人和波次均不推进。

## 7. 输入优先级与失败反馈

输入优先级固定为：系统暂停/终局 > 词条选择 > 改造弹层 > 建筑操作。纯 `decideGrowthPointer`/同等适配层先判断坐标是否命中当前模态，再由 GameScene 翻译为核心命令。

同一指针事件不能同时触发模态按钮与格位动作。非法或不可支付动作只显示 1.2～1.8 秒的明确提示，典型文案为“还差 N 木材”“还差 N 金币”“建筑已达到 Lv.5”“当前没有合法目标”。

成功动作优先通过资源数值、建筑等级、词条/改造视觉和短提示表达；避免长期常驻说明遮挡战场。

## 8. 动效与图标

- 建筑选中：120～180ms 暖白描边和功能色内辉；
- 合法目标：120～180ms 一次淡入，不循环剧烈呼吸；
- 建造落地：240～320ms 轻弹与尘圈；
- 资源扣除：180～260ms 数值即时变化，表现可短暂插值；
- 错误：100～160ms 小幅拒绝反馈，不震动全屏；
- 跨过资源阈值可有一次克制亮边，不循环闪烁。

资源、塔种、暂停和危险图形使用厚轮廓、低细节、自绘实心符号，不使用不统一的 Emoji。木材使用暖木色/琥珀色，金币使用亮金色；四塔功能色沿用机枪黄、火炮橙红、冰冻青蓝、电磁紫白。

## 9. 状态流

```text
OPENING_COUNTDOWN → RUNNING ↔ TACTICAL_PAUSE
                         ↓
                    TRAIT_DRAFT
                         ↓
              RUNNING / TACTICAL_PAUSE
                         ↓
                 VICTORY / DEFEAT
```

倒计时、暂停、词条选择、系统暂停和重开均由 core 状态驱动。胜负后不再接受建造、升级、改造或拆除；重开只通过终局入口执行。

## 10. Phaser 边界

`src/core` 负责固定格位、波次、敌人、城墙、资源、成长建筑、攻击、词条、改造、暂停、终局和拒绝原因。

`src/phaser` 负责布局、绘制、点击坐标、模态层级、动画和反馈。GameScene 不复制费用、等级上限、产速、词条累计或战斗公式；所有可见派生来自 typed content/selector。

## 11. 候选版验收

- 运行时与导出中不存在旧卡牌/补给/永久/战术/弃置入口、类型、命令或状态；
- 10 波组成、16 脉冲和敌人数值与 core 测试一致；
- 箭塔→特殊塔改造、改造后升级/专属词条、木材厂升级/产速和同类建筑来源隔离均有回归；
- 720×1280 与 360×640 均无重叠、裁切、控制台 error/warn；
- 阶段 D evidence 记录测试、静态 grep、浏览器截图与已知风险；
- 旧阶段文档、历史截图和 Mission Brief 可保留为历史材料，不是当前运行版事实源。
