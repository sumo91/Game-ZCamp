# ZCamp 主战场 UI 矢量母版

> 状态：D3 已确认，可用于视觉扩展与 Phaser 实现基准。  
> 主文件：[zcamp-battle-ui-d3-vector.svg](./zcamp-battle-ui-d3-vector.svg)  
> 渲染预览：[zcamp-battle-ui-d3-vector-720x1280.png](./zcamp-battle-ui-d3-vector-720x1280.png)

## 使用定位

该 SVG 是主战场的**视觉与布局母版**，负责固定 720×1280 基准画布、纵向区域比例、5×3 格位、建筑锚点、HUD、木材轨道、四卡结构、颜色和矢量造型语言。

它不应作为整张不可交互背景直接覆盖到游戏中。Phaser 应按母版坐标分别实现战场、单位、城墙、格区、建筑、资源轨道和手牌层，核心规则继续来自 `src/core`。

## 稳定开发接口

| 对象 | SVG 标识 | 基准范围 / 规则 |
|---|---|---|
| 敌军战场 | `region-enemy-field` | `y=0～724` |
| HUD | `hud` | 叠加在敌军战场，不独占高度 |
| 敌人层 | `enemy-layer` | 远小近大，向城墙推进 |
| 战斗特效层 | `combat-vfx-layer` | HUD 与手牌不得被特效覆盖 |
| 城墙 | `wall` | `y=708～772`，耐久嵌在墙体 |
| 5×3 棋盘 | `region-defense-grid` | `y=772～1090` |
| 15 个格位 | `slot-r{row}-c{column}` | 5 列×3 行，单格 `128×94` |
| 建筑层 | `building-layer` | 建筑通过 `data-slot` 绑定格位 |
| 木材轨道 | `resource-rail` | `y=1090～1138` |
| 四卡手牌 | `card-hand` | `y=1138～1280` |
| 卡牌 | `card-machine-gun` 等 | 使用 `data-card`、`data-cost` |

完整尺寸也保存在 SVG 的 `zcamp-layout-metadata` 中，便于校验或生成开发常量。运行时不建议每帧解析 SVG；应把确认值同步为类型化布局常量，并通过测试防止漂移。

## 可扩展部分

- 在 `<defs>` 中新增或精修敌人、建筑、图标和 VFX 符号；
- 为现有符号增加受伤、禁用、选中、升级和破损变体；
- 从矢量符号导出独立 PNG/WebP 或 Texture Atlas；
- 在不改变区域顺序的前提下适配更长或更矮屏幕；更长空间优先增加敌军纵深；
- 复用统一卡壳制作更多内容定义，但主战场同时只显示四张卡；
- 复用 `slot-r{row}-c{column}` 建立点击热区、合法格、高亮和建筑锚点。

## 不可随意改变

- 敌军区、城墙、格区、资源轨道、四卡的纵向语义顺序；
- 固定 5×3、15 个同尺寸格位；
- 城墙紧贴前排，不增加炮台走廊；
- 木材轨道必须位于格区与手牌之间；
- 四张卡的固定位置和木材成本语义；
- 主战场不增加开波按钮；
- 粗外轮廓、大块面、两档明暗和低细节噪声的视觉语言。

## 推荐实现流程

1. 将 SVG 中的画布、区域与格位坐标同步为类型化布局常量；
2. Phaser 使用独立 Container / GameObject 建立各层，不把整屏 SVG 当作单张 Sprite；
3. 将可复用符号按显示尺寸导出为透明 PNG/WebP 或图集；
4. 卡牌名称、成本、图标键和建筑定义从类型化内容数据读取；
5. 选择、建造、资源不足、城墙受损、商店和倒计时由运行时状态驱动；
6. 通过 720×1280、360px 宽截图和交互热区测试验证实现没有偏离母版。
