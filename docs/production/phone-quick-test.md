# 手机扫码快速测试

这是 #5 表现资产候选的取证入口，不构成实体手机或项目所有者的人工接受。正式混编与核心持续攻击验收仍保持原有边界。

先在干净、已提交的候选工作树执行 `npm run check`、`npm run build`，记下 `git rev-parse HEAD`。本地收件服务只服务指定 dist；运行者须保证 dist 来自记录的候选 SHA。

```powershell
node scripts/phone-collector.mjs --host <电脑实际局域网地址> --port <指定端口> --dist <候选dist绝对路径> --output <取证目录绝对路径> --build-sha <完整候选SHA>
```

必须显式指定本机已分配的局域网地址，禁止通配绑定。脚本不会修改防火墙、网络或调试设置。output 必须位于公开 dist 之外。默认生成随机会话 token；需要恢复已记录入口时，可传 `--token <会话token>`，但服务器会建立新会话身份。终端输出本次入口 URL，将这个 URL 转成真实二维码。不要将私人地址或真实会话 token 提交到仓库。

入口格式：`http://<host>:<port>/Game-ZCamp/?preview=asset-pressure&phone=iqoo-z10-turbo&session=<随机token>`。手机保持同一局域网，扫码打开。网页确认电脑收件服务与画面已就绪后，点击“开始手机测试”。保持前台，触摸“触摸响应检查”记录真实输入响应。三轮分别是标准画质 100单位/60秒、200单位/300秒、300单位/60秒，每轮预热5秒，总测量与预热约7分15秒，回传与加载另计。

补测入口在同一格式末尾添加 `&from=2`：显示“补测第二、三轮 · 约6分10秒”，按钮“开始剩余两轮”。第1轮标注“本入口不测，使用电脑已保存记录”，不制造完成记录或回执；参数只选择本页面要测的轮次，不证明外部证据存在或已验收。`from=3` 只补第3轮，约1分5秒。只接受精确的1/2/3值，其他值按完整三轮处理。

入口预填来自项目所有者的设备声明：实体手机、iQOO Z10 Turbo、Android（具体版本待核实）、已连接 Vivo 办公套件（实际投屏负载待核实）。高级设置可修正设备类别、型号、系统与备注。桌面 QA 必须改为真实桌面声明；仅打开手机预设不能证明真机。记录同时保留实际浏览器环境提示、声明来源与待核实字段，人工接受始终为 false。

每轮完成或中断才发送该轮完整原始 JSON，包括全部慢帧、响应记录、场景和清单身份。服务验证会话 token、必要原始字段及8 MiB大小上限；完整独占写入并同步唯一文件后才返回成功回执。页面收到回执后显示“电脑已收到”并开始下一轮。output 另保存会话与候选构建 SHA，不改变资产清单的历史来源身份。

后台、旋转/窗口变化、图形上下文丢失、手动停止和发送失败都会停止序列，并保留已完成及当前中断结果。返回前台、画面恢复且本次所有记录取得实际收件回执后，可点击“继续未完成测试”。中断轮重新预热5秒、重新连续完整采样，独立 `phoneTest.round`/`attempt` 记录，不拼接旧帧、不缩短时长。完整完成但发送失败的记录重试送达后，显式继续进入下一轮，不重测已完整轮。发送中或失败未送达时继续按钮不可用；全部本入口轮次完整送达后不再提供继续。补测完成只显示“本入口补测完成”，不能证明之前轮次或人工设备接受。

失败时可重试同一 JSON 或导出全部备援；重试不会静默继续未测轮次，也不会重测清空成功轮次。轮次表聚合所有独立attempt，区分完整完成与已保存的中断。结果在当前页面内存与已成功落盘文件保留；关闭/刷新页面可能失去尚未送达的内存备援，应先导出。浏览器终止页面时网络发送无法保证完成。这个限定续测功能不跨页面、浏览器或会话恢复历史。

没有电脑收件服务或会话 token 时，快速模式明确提示使用扫码入口并禁止开始，避免假回传。原高级实验入口 `?preview=asset-pressure` 继续提供独立配置、手动测量与原始 JSON 导出。

公共回归边界：`npm run check` 包括入口预填、三轮保存/中断/重试行为，以及真实HTTP收件、磁盘写入失败、错误token、无效/超限JSON、编码路径与符号链接越界。公开UI与手机可达性仍须独立实测；桌面流程验证不能充当三轮手机性能数据。
