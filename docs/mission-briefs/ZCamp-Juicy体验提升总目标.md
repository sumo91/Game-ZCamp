# Mission Brief: 尸潮营地 Demo 的 Juicy 反馈与基础手感

## Intent

当前 Demo 的核心模拟与事件流已完整，但表现层缺乏状态之间的过渡：无声、无补间、无镜头语言，击杀、资源、受击与关键时刻都没有体感。本任务在不改动玩法与内容的前提下，把已有事件流转化为可感知的反馈，使 Demo 的基础体验"更 Juicy、更带感"。

## Desired Outcome

- 战斗、建造、升级、改造、词条、胜负等玩家可见瞬间具备分层且不过载的听觉与动效反馈；
- 输入具备即时手感：按钮按压反馈、弹窗入场过渡、资源数字变化反馈、失败操作的强提示；
- 重要战斗事件（城墙受击、死亡、冲锋、Boss、波次）在不牺牲可读性的前提下有差异化表现；
- 关键时刻（波次开始、Boss 出场、词条三选一、结算）具有仪式感。

## Success

- 游戏具备可开关的程序化音效，尊重浏览器自动播放策略（首次交互解锁），高频音效有节流，持续战斗不产生噪音墙；
- 所有可点控件具有按压反馈；主要弹窗有入场过渡；资源数字在明显变化时有可感知反馈；
- 战斗通知不再单行抢占：全局事件、预警事件、高频战斗提示分通道呈现或节流；
- `src/core` 无行为改动；`npm run check` 全绿，新增反馈决策逻辑以纯函数实现并纳入测试；
- 玩家可见变化附可复现的测试或视觉验证证据。

## Evidence Required

- `npm run check` 全绿（含新增反馈纯函数测试）；
- 变更范围证明：`src/core` 无 diff；
- 720 与 360 逻辑分辨率下的运行截图，覆盖新增反馈的关键界面状态；
- 玩测记录：静音开关、首次交互解锁、按钮/弹窗反馈、通知分通道的实际观察。

## Boundaries

- 遵守 AGENTS.md 确定性边界：模拟保持在 `src/core`、平台无关、可种子复现；Phaser、DOM、WebAudio 只存在于 `src/phaser` 边界层；
- 遵守 TEAM_PROTOCOL 角色边界：不新增美术素材文件、不改配色与视觉语言；动效与占位图形沿用现有矢量风格。若确需视觉规范变更，先取得总制作人/艺术总监确认；
- 音频一律程序化合成（零新增素材），提供静音开关（含记忆），并尊重浏览器自动播放策略；
- 反馈路由、节流、强度分层等决策逻辑抽为无 Phaser 依赖的纯函数并测试（沿用 `growthUi.ts` 模式）。

## Non-goals

- 不对齐 MVP 文档（20 波、挑战任务、尸潮成长、局外成长）（项目所有者已明确）；
- 不新增玩法内容（敌人、波次、英雄、建筑、词条数量）；
- 不做美术重制、风格变更或新素材导入。

## Context

- 事实源：`AGENTS.md`、`docs/production/TEAM_PROTOCOL.md`；
- 表现层现状：`src/phaser/GameScene.ts` 每帧直绘，无 tween/音频/粒子；`GameEvent`（`src/core/types.ts`）已覆盖全部可表现瞬间，是反馈层的主要输入；
- 分阶段执行（J1 感官地基 → J2 战斗可读性 → J3 仪式感 → J4 结构优化）为执行选择，不构成审批点；阶段内顺序自由。

## Execution Authority

- 授权：`src/phaser` 内的实现（含新建 fx 模块与必要的 GameScene/LobbyScene 重构）、新增测试、`docs/evidence/` 证据产出、运行本地 dev server 与构建检查；
- 需先确认：任何 `src/core` 行为改动、美术素材/视觉语言变更、对外发布与导出、git 提交。
