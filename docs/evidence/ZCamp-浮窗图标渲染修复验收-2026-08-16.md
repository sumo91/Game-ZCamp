# ZCamp 浮窗图标渲染修复验收（2026-08-15/16）

来源：项目所有者反馈——浮窗按钮只有消耗图标+数字，建筑本体图标缺失。排查中发现一个影响深远的渲染问题，本轮一并记录。

## 根因（Phaser 4.2.1 引擎问题）

**`Graphics` 的 path 类填充（`fillTriangle`/`fillPoints`→`FILL_PATH`）在游戏运行时静默失效**，只有 `fillRect`/描边类可靠。排查路径：

1. 隔离测试页（同 Vite、同 Phaser 包、Canvas/FIT/每帧 clear 重绘）：四种原语全部正常 → 引擎 API 本身可用；
2. 游戏内 create 期间创建的 Graphics：path 填充无输出（命令在缓冲中、无异常、对象可见）；
3. 运行时（场景运行中）新建的 Graphics：同一场景内 path 填充**完全正常**；
4. 结论：与对象生命周期/场景状态相关的引擎缺陷，精确机制未继续深究（已消耗大量时间，收益递减）。

该问题意味着**主城三角屋顶、箭塔/冰冻塔尖、Boss 头冠、精英肩甲自项目开始就未渲染过**（占位美术下一直未被察觉）。

## 修复策略

- **浮窗图标改为 Text 几何字形**（▲ 箭塔 / ■ 木材厂 / ↑ 升级 / ★ 改造 / × 拆除）——Text 管线在两种渲染器下始终可靠（费用数字从未出过问题即为证）；
- 保留**脏检查重绘**（配置无变化不重绘），消除每帧 clear+重画的时序暴露面；
- 费用行保留（数字 + 资源小图标），资源不足时数字变红；
- 顺手把全项目 10 处 `fillTriangle` 调用统一改为 `fillPoints` 封装（`src/phaser/fx/draw.ts`），虽然 dynamic 图层的 path 问题未根治，但代码路径一致，待后续换 Phaser 版本时统一恢复。

## 验证

- `npm run check`：102 测试全绿。
- 像素级验证（Canvas 模式，`toDataURL` 回读）：
  - 箭塔按钮金色 ▲：346 像素 ✓；木材厂按钮绿色 ■：400 像素 ✓；费用数字 53 像素 ✓；
- WebGL（AUTO 常规模式）：浮窗建造路径回归通过（选中→点图标按钮→木材 120→60、选中自动清除）；Text 渲染在 WebGL 下的可靠性由费用数字长期表现背书。
- 截图：`docs/evidence/zcamp-icon-bar-text-glyphs-720.png`。

## 遗留（记录，非本轮范围）

- `dynamic` Graphics（战场层）的 path 填充仍不渲染：主城/箭塔/冰冻塔尖顶、Boss 头冠、精英肩甲不可见。占位美术下影响有限；候选方案：升级 Phaser 4.x 小版本验证是否已修、或把这些 glyph 迁移为 Shape/Text 对象。建议列入下轮迭代。
