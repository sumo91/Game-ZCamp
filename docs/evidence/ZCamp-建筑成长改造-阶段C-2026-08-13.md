## 实现范围

- `src/phaser/growthUi.ts` 提供平台无关的成长 UI 派生与输入决策：空格两种建造、当前/下级属性、升级费用、木材厂产速、四路改造、pending 词条顺序与输入优先级。
- `GameScene` 将玩家入口切换为 5×3 固定格、情境操作面板、四路改造 modal 和强制三选一 modal；旧手牌、供给、弃牌和补给入口不再渲染或接收输入。
- 木材、金币和木材产速均读取核心状态/selector；Phaser 仅发送 `build_building`、`upgrade_building`、`transform_tower`、`choose_building_trait`、`destroy_building`。
- 隐藏的系统/改造/词条/结算层显式禁用输入；格位点击通过逻辑画布坐标适配，避免透明对象在缩放下吞掉点击。

## 浏览器路径

本地 `npm run dev -- --host 0.0.0.0 --port 5191`，页面自身控制台 `error/warn` 为空。

1. 720×1280 新局：点击第 1 排第 1 格，看到“建造箭塔｜木材 40 / 建造木材厂｜木材 60”；点击箭塔后看到 Lv.1 属性、下级属性、木材升级费、改造和拆除。
2. 720×1280：点击升级，核心进入 `TRAIT_DRAFT`，战场降亮并显示当前建筑格位、Lv.2 和原顺序的三个通用词条；底层格位/暂停不可穿透。
3. 360×640：同一格位点击和两项建造按钮仍可命中，无横向滚动；资源栏、格位和操作面板不重叠。
4. 360×640：建造箭塔后打开改造，四个特殊塔以 2×2 同时显示，含名称、职责、形状/功能色、金币费用和不可支付状态。
5. 战术暂停期间仍可进行格位/建筑规划；升级成功后的词条选择由核心阶段驱动，UI 不自行恢复战斗。
6. 改造 modal 内点击金币不足的路线时，面板保持打开并在标题下显示“还差 10 金币”，不扣资源、不改变建筑。
7. 连续真实路径：开局建两座箭塔；首波末通过格位入口补建木材厂；第二波升级一座箭塔并完成通用词条选择；恢复战斗后采样到第 3 波，波次、敌人数和资源继续由核心推进。
