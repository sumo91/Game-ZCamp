## 实现范围

- `src/phaser/growthUi.ts` 提供平台无关的成长 UI 派生与输入决策：空格两种建造、当前/下级属性、升级费用、木材厂产速、四路改造、pending 词条顺序与输入优先级。
- `GameScene` 将玩家入口切换为 5×3 固定格、情境操作面板、四路改造 modal 和强制三选一 modal；旧手牌、供给、弃牌和补给入口不再渲染或接收输入。
- 木材、金币和木材产速均读取核心状态/selector；Phaser 仅发送 `build_building`、`upgrade_building`、`transform_tower`、`choose_building_trait`、`destroy_building`。
- 隐藏的系统/改造/词条/结算层显式禁用输入；格位点击通过逻辑画布坐标适配，避免透明对象在缩放下吞掉点击。

## 浏览器路径

本地 `npm run dev -- --host 0.0.0.0 --port 5191`，页面自身控制台 `error/warn` 为空。

1. 720×1280 新局：点击第 1 排第 1 格，看到“建造箭塔｜木材 40 / 建造木材厂｜木材 60”，两项均带自绘木材图标、职责和状态；点击箭塔后看到 Lv.1 属性、下级属性、木材图标/升级费、金币图标/改造入口和拆除。
2. 720×1280：点击升级，核心进入 `TRAIT_DRAFT`，战场降亮并显示当前建筑格位、Lv.2 和原顺序的三个通用词条；底层格位/暂停不可穿透。
3. 360×640：同一格位点击和两项建造按钮仍可命中，无横向滚动；资源栏、格位和操作面板不重叠。
4. 360×640：建造箭塔后打开改造，四个特殊塔以 2×2 同时显示，含名称、职责、功能色/形状、金币自绘图标、费用和不可支付状态；四项与返回按钮均未裁切或重叠。
5. 战术暂停期间仍可进行格位/建筑规划；升级成功后的词条选择由核心阶段驱动，UI 不自行恢复战斗。
6. 720×1280 低金币时，箭塔详情的“改造｜金币 10”入口仍可打开；四个改造选项均保留可读费用并显示“金币不足”，点击选项不扣资源、不改变建筑。
7. 连续真实路径（正常 UI、未注入状态）：开局建两座箭塔；第 1 波将右侧箭塔升至 Lv.2 并选通用词条；第 2 波用核心击杀金币将该塔改造成炮塔；第 3 波建木材厂；第 4 波将木材厂升至 Lv.2 并选 `双班制`，产速从 `+1.5/秒` 变为 `+2.5/秒`；第 5 波将炮塔升至 Lv.3 并看到 `扩爆 · 炮塔专属`。另一座箭塔仍为普通 `箭塔 Lv.1`，未继承炮塔专属词条。
8. 720×1280 综合截图还确认资源栏、操作按钮和改造/成长模态未重叠；360×640 初始页及空格操作确认 5×3 格区、木材/金币栏、操作按钮均在画布内可见；四张截图均由本轮最终代码重新生成；该浏览器页 `error/warn` 日志为空。
