# ZCamp 建筑成长改造·阶段 B 验收记录

日期：2026-08-13
分支：`codex/tower-evolution-v0.2`；绑定基线：`3ca7172`

## 范围

本阶段只接入 `model: "growth"` 建筑的核心战斗与经济结算，没有切换 Phaser UI、删除旧卡牌、修改 master 或发布 Pages。旧 `model: "legacy_card"` 建筑继续走原有攻击、永久卡和木材路径；growth 塔在旧 `resolveTowerAttacks` 分支中被明确隔离，growth 木材厂也不进入旧木材厂表。

## 派生与来源边界

- growth 塔攻击画像由 `src/core/growthCombat.ts` 派生：当前塔型基础定义、`1 + 0.20 × (level - 1)` 伤害倍率、`1 + 0.10 × (level - 1)` 攻速倍率、当前建筑自己的通用/专属词条。
- 通用伤害、贴墙、收割、精英/Boss 条件均按本塔当前目标快照计算；机枪穿透与电磁链按位置再 ID 的稳定顺序选择目标。
- 燃烧和减速存储在敌人的 `growthBurnStates` / `growthSlowStates` 中，每项都保留 `sourceBuildingId`。同类塔状态独立；拆除来源塔立即清除状态，并且后续 tick 会再次过滤无效来源。
- 冰霜安全下限为命名常量 `GROWTH_FROST_MIN_SLOW_MULTIPLIER = 0.1`。冰霜易伤只检查当前塔自己的来源减速。
- growth 木材厂由 `src/core/growthEconomy.ts` 逐座计算：`(等级基础产量 + 0.4 × lumber_flat 层数) × (1 + 0.25 × lumber_output 层数)`；升级折扣沿用阶段 A 的 `getGrowthUpgradeCost` 舍入并封顶 35%；波次储备按仍存在的木材厂逐波触发一次。
- 主城 0.5/秒、旧木材厂与旧永久木材收入仍由共享 `getWoodProductionPerSecond` 合并；暂停、词条选择和系统暂停不进入 running tick。
- 炮塔溅射 `0.45` 与电磁弹射 `0.55` 已进入 typed tower definition，并由 validator 校验；机枪穿透的 `0.7` 继续来自词条 effect。
- 持续燃烧使用不带单次命中最低 1 的 core 入口，只应用敌人既有 `damageMultiplier`；新鲜燃烧在攻击发生后的步内剩余时间结算。刷新时记录步首同来源的旧覆盖区间，将燃烧状态寿命与本步未覆盖伤害区间分开推进，避免旧状态与刷新状态双算；同一来源仍只有一个状态，不同来源可并存。减速按来源到期边界分段积分，多来源取当前最强倍率。攻击冷却保留步内 overshoot。

## 自动化证据

新增 `tests/core/growthCombat.test.ts` 与 `tests/core/growthGame.test.ts`，覆盖：

- 箭塔及四种改造塔攻击贴墙敌人；等级、伤害、攻速、射程与改造重算；通用六类词条；八类特殊塔词条；
- 五种塔各 Lv.1/Lv.3/Lv.5 的伤害、攻击间隔、射程表驱动断言；改造后的同等级 profile 从新塔定义重算；
- 机枪穿透、炮塔溅射/燃烧、冰霜深寒/来源易伤、电磁链/过载；持续状态叠层不复制触发器；
- 两座同类塔的词条隔离、旧 `permanentApplications` 不作为 growth 塔增益、growth/legacy 不重复攻击；
- 拆除后的状态清理与无幽灵伤害；两座木材厂的产量、折扣、波次储备和拆除隔离；
- 两座仍存活木材厂在 wave1/wave2 各按自身层数只结算一次，另保留拆除后不触发回归；
- 战术暂停、强制词条选择期间的木材/敌人/有效战斗时间冻结；预置燃烧总伤害、真实 cannon 在 active burn 期间刷新（含旧状态先到期与后到期两种顺序）、两座炮塔来源并存及拆除一座后的剩余来源，均在 0.25、0.125 和 30Hz 合法 tick 切分下保持确定性；减速跨到期点、多来源减速和多次攻击同样保持确定性；目标 ID 使用显式 locale 无关比较器。
