# ZCamp 连续尸潮动态卡牌版四阶段验收报告

> 日期：2026-08-12  
> 结论：四个实现阶段均已验收，可作为首版完整可玩验证基线。  
> 边界：本结论不等于最终美术资产、发行性能或长期运营数值已经完成。

## 3. 最终体验检查

- 正常入口只出现一次 5 秒开局倒计时，倒计时内允许建造但战斗、生产和补给不推进。
- 十波按有效战斗时间连续到来；上一波未清不会阻止下一波；不存在波间商店、手动开波或 Buff 三选一。
- 战术暂停冻结世界与收益但保留基地规划和出牌；系统暂停冻结并阻断全部玩法输入。
- 四格手牌、下一补给、满手等待、弃牌、木材/金币成本、合法目标和真实升级费用均可在主战场读取。
- 敌人核心进度在 Phaser 中映射为从上向下压向城墙，横向 lane 只由稳定敌人 ID 决定；核心模拟和目标选择未因表现调整而改变。
- 第 5 波冲锋领主与第 10 波尸潮君王均有独立、可读的技能反馈；最终 Boss 死亡立即胜利，城墙归零立即失败。
- 终局阻断继续操作，隐藏暂停，停止补给并显示重开入口。

## 4. 自动化与构建

最终独立复核结果：

- `npm run check`：通过，4 个测试文件、34 项测试全部通过；
- `npm run build`：通过；
- `git diff --check`：通过，仅存在 Windows 行尾转换提示；
- 正常玩家源码未发现阶段、基线、速度倍率或开发说明标签；
- 生产 bundle 中演示查询字符串仍可能因打包方式保留，但 `showcaseMode` 被折叠为常量 `false`，正式构建不可启用开发加速/冻结入口；
- 关键浏览器证据页控制台无 error / warn。

生产构建仍报告 Phaser 主 bundle 超过 500 kB 的提示；这不是本阶段构建失败，但应在发行性能阶段单独处理。

## 5. 可玩路径记录

- 正常入口、完全不操作：第 1 波城墙失守，证明失败路径、墙体归零和输入阻断有效。
- 开发态确定性加速、实际部署四种功能建筑：到达第 10 波并击杀最终 Boss，最终击杀 232、城墙 100/100，证明十波时间线、真实建造与胜利路径可闭环。
- 加速只改变本地验证的现实等待速度，不改变核心有效时间、牌序、伤害、波次或胜负规则；正式构建不可启用。

这组结果证明“合理操作可赢、完全不防守会输”，但尚不足以代表长期数值平衡。后续应以真人正常速度试玩继续观察构筑多样性、暂停频率、资源余量和第 5～10 波压力曲线。

## 7. 已知非阻塞项

- 敌人、建筑、卡牌和 VFX 仍以 Phaser 几何组合为主，已达到可辨识的首版产品表现，但后续仍需正式资产替换与动效/音频打磨。
- 360px 已验证信息和区域不被裁切；正式移动端触控手感仍需真机复核。
- 当前几何表现保持 D3 的结构、色彩和轮廓方向，但不是对正式 SVG 细节的逐像素复刻。
- 尚未做发行包体、低端设备帧率、首包资源和长时间内存专项。
