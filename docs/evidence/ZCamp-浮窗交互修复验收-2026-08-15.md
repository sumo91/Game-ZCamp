# ZCamp 浮窗交互修复验收（2026-08-15）

来源：项目所有者玩测反馈（三项）。对应 Mission Brief：`docs/mission-briefs/ZCamp-Juicy体验提升总目标.md`（同 commission 下的缺陷修复）。

## 反馈与修复

| # | 反馈 | 修复 |
|---|---|---|
| 1 | 建造木材厂后，浮窗直接弹在点击位置（自动选中新建筑） | `performBuild` 成功后 `clearSelection()`，浮窗随选中一起消失 |
| 2 | 浮窗菜单与底部建筑按钮同时存在，冗余 | 移除底部三个操作按钮及其渲染/输入管线；底部面板保留为信息展示 |
| 3 | 浮窗无法关闭，只能切换选中其他格子 | 点击战场空白/底部面板/HUD 即关闭；点击浮窗底板空白段也关闭 |

## 过程中发现并一并修复的缺陷

- **按钮-场景双触发**：浮窗按钮与场景级 pointerdown 同时命中。验证时复现"建造后同一点击又选中了按钮下方格子"。修复：`suppressScenePointer` 一次性标志，浮窗按钮动作后吞掉同一次场景级点击（标志在处理器顶部消费，不会泄漏到下一击）。
- **浮窗布局遮挡**：原三档列锚点会让浮窗盖住选中格子自身/其他行格子。重写 `deriveSlotActionBarBounds`：水平跟随格子列并钳制在屏内；第 1 排浮窗放城墙条上（格区上方无空间），第 2/3 排浮窗落在上一排与本排之间的空隙带（部分覆盖上一排建筑下半部，瞬态）。
- 新增 `pointInLogicalBounds` 纯函数与 `tests/phaser/layout.test.ts`（全屏内、不遮选中格、边界命中语义，4 项测试）。

## 验证

- `npm run check`：97 测试全绿（新增 4 项 layout 测试）。
- 浏览器回归（720×1280，画布点击 + `__zcampDebug` 交叉验证）：
  - 浮窗建造木材厂：木材 120→60，选中自动清空，无串选；
  - r3 排（后排）格子可正常选中，浮窗不再遮挡任何格子本体；
  - 点击战场空白 → 浮窗关闭；点击浮窗底板空白段 → 关闭；
  - 浮窗升级按钮 → 正常进入词条三选一；
  - 第 1 排浮窗（城墙条位置）建造箭塔路径正常（120→80）。
