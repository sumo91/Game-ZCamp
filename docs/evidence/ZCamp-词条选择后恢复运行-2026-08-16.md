# 词条选择后恢复运行验收 · 2026-08-16

## 背景

项目所有者反馈：升级触发的词条三选一会冻结战斗，但选完后游戏仍停在战术暂停，需要玩家手动恢复，体验不顺。决定改为：选择一个词条后游戏立即恢复继续。

原行为来自 v0.2 设计稿 §7.2（"从 RUNNING 中升级：选择完成后仍保持战术暂停"），属设计变更而非缺陷；已同步改写设计稿并注明决定与日期。

## 新语义

- 升级发生时的相位即选择完成后的回归相位（`returnPhase = currentPhase`）：
  - 运行中升级 → 选完**立即恢复运行**；
  - 战术暂停中升级（玩家主动暂停）→ 选完**保持战术暂停**，保留玩家意图；
  - 开局倒计时中升级 → 选完恢复原倒计时（不变）。
- 词条选择期间世界冻结、其他操作阻断等语义不变。

## 变更

- `src/core/game.ts` `upgradeGrowthBuilding`：`returnPhase` 由"非倒计时一律战术暂停"改为直接沿用当前相位。
- `tests/core/growthCore.test.ts`：原"选完回战术暂停"用例改为"恢复升级前相位并保留主动暂停"（RUNNING→RUNNING、TACTICAL_PAUSE→TACTICAL_PAUSE、倒计时→倒计时三路断言）。
- `docs/尸潮营地_建筑成长改造_阶段版本设计_v0.2.md` §7.2：按新语义改写并标注 2026-08-16 项目所有者决定。

## 验证

- `npm run check` 全绿（110/110）。
- 实机（正常速度、WebGL）：建造箭塔（木 120→80）→ 升级（扣 50，浮窗三选一弹出，选项 tower_range/tower_attack_speed/tower_wall_guard）→ 点选第一项 → 相位回 `RUNNING`，战斗时间 1 秒内 88.16→89.17 持续推进，暂停遮罩/徽标随相位自动消失。截图：`zcamp-trait-draft-modal.png`（选择中）、`zcamp-trait-after-choice-resumed.png`（选完恢复）。
- 战术暂停路径由单元测试锁定（升级于 TACTICAL_PAUSE → 选完仍 TACTICAL_PAUSE）。

## 备注（验证过程中的工具性发现，非游戏缺陷）

- 格子 ID 为 1 起数（r1=顶行，主城 r3c3）；浮窗按钮位随可见按钮数自适应（2 钮 button0 在 x≈171，3 钮在 x≈118），自动化取证需按 `__zcampSlotBar.bounds` 取点。
